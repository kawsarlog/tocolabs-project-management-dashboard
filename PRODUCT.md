# Product

## Register

product

## Users
This product serves two primary user groups inside a business workspace.

The first user is the business admin or operations lead. They use the product to monitor employee output, track order activity, review notes, spot pending work, and understand revenue and delivery patterns across the team. Their context is operational oversight: they are not the main data-entry user, they are the observer, reviewer, and decision-maker.

The second user is the employee. Each employee maintains a personal work sheet inside the product, similar to an Excel ledger. They log daily shift activity, add multiple order rows under a given date, update statuses, add notes, and keep their own work history organized.

## Product Purpose
This is a TocoLabs SaaS product for turning spreadsheet-based team tracking into a structured multi-tenant web application.

The core job is to preserve the flexibility of employee-owned sheets while giving admins a much stronger observability layer. Employees should feel like they are working in a clean, fast, sheet-style ledger. Admins should feel like they are inside a premium operational cockpit where they can open any employee's work log, inspect it in detail, filter it by month or status, and understand exactly what is happening across the team.

Success looks like this:
- employees can maintain their own work sheet without friction
- admins can review each employee's detailed activity without asking for separate files
- the team dashboard summarizes orders, revenue, and work status clearly
- the interface feels like a real SaaS product rather than a spreadsheet clone or a generic admin template

## Brand Personality
TocoLabs should feel:
- precise
- premium
- focused

The tone should be calm, modern, and operationally confident. This is not a playful consumer product. It should feel trustworthy, structured, and intentional, similar to the confidence users get from well-made internal tools like Linear or Notion, but adapted for team tracking and observability.

## Anti-references
This product should not look like:
- a generic free admin template with shallow cards and weak hierarchy
- a colorful, noisy, childish task manager
- a project-management CRUD app where the admin creates everything and employees only fill rigid forms
- a literal Excel copy with poor readability and no product identity

## Design Principles
1. Preserve sheet freedom, add product clarity.
Employees should still feel like they own a flexible working sheet, but the product should make the workflow cleaner, faster, and easier to review.

2. Admin value comes from observability, not forced control.
The admin experience should focus on visibility, filtering, summaries, and comments rather than owning every data-entry action.

3. Dense information must still feel premium.
This product contains operational data, tables, and repeated rows. Density is acceptable, but clutter is not.

4. Familiar workflows beat clever reinvention.
The product should improve the existing spreadsheet workflow without turning it into an unfamiliar project-management tool.

5. Every screen should help answer "what happened, who did it, and what needs attention?"
The dashboard, employee sheet, and detail views should all reinforce fast understanding and review.

## Accessibility & Inclusion
The UI should target WCAG AA readability.

Requirements:
- strong text contrast on all surfaces
- reduced-motion support
- keyboard-friendly data entry where possible
- status indication should not rely on color alone
- dense tables must remain readable on laptop screens and responsive on smaller screens
